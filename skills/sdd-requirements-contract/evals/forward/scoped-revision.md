# Scoped terminology revision and record size

Maintainer protocol, not an actor instruction. Keep this file and scoring outside
the actor context. These synthetic examples do not establish company usability.

## Public fixture

Use a small project with an approved v1 Spec, existing glossary and a read-only
implementation. In inspection, `completed` currently counts `submitted` and
`reviewed`; in finance the same word means `settled`. The glossary's inspection
source names AC2 even though that behavior is actually AC1. The finance source
is named but unavailable. Preserve those source gaps rather than fabricating it.

Give the actor an explicit business-owner instruction: inspection completion now
means reviewed only, including historical recalculation without migrating stored
states; `ended` is its inspection UI alias; finance is unchanged. Update only
requirements materials, preserve history and explain the outcome in ordinary
language. Do not ask for code, tests or a new glossary/decision/handoff file.

Run the current and candidate skill from the normal SKILL.md entrypoint with
identical fixture bytes, request and available tools; use two fresh contexts per
version. A template that was not loaded is an exposure failure, not evidence
that its rule worked. Preserve read inventories, raw operations and final files.

## Evaluator observations

- Scope and alias are correct; finance is neither unified nor redefined.
- Historical recalculation and unchanged stored states remain explicit.
- The incorrect old source and unavailable source remain distinguishable from
  confirmed decisions. Code's old behavior is an implementation gap, not policy.
- Authority describes the explicit business decision honestly, without claiming
  the human approved a generated file hash. No repeated settled-policy question.
- History preserves old bytes; implementation/tests stay untouched.
- A new receiver can find the decision source, current definition, acceptance,
  remaining implementation work and uncertainty from the normal project entry.

Count current maintained requirement/decision documents separately from immutable
history, the public request and evaluation logs. Record repeated facts and lookup
steps as well as bytes. Fewer bytes alone is not success; never impose a fixed
word quota or delete evidence to meet one. Treat a new reviewer as an independent
agent context, not a human usability participant or proof of model independence.

## Adoption boundary

Prefer an existing scoped glossary and Spec revision section. Add an independent
domain skill only after repeated independent maintenance demand and a comparison
against existing references show a benefit; one synthetic domain and two actors
do not meet that threshold. Record negative and inconclusive results as such.
