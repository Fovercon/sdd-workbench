# First-task and proportional-routing forward evaluation

Maintainer-only. Freeze baseline/candidate skills and identical raw input hashes;
keep this rubric, preparer, receipts and other variants outside actor context.
The preparer emits ordinary synthetic projects, not scoring hints or an expected
route label. Read the task rules about instrumentation versus product mutation.

```sh
python3 skills/sdd-workflow-router/evals/forward/prepare_entry.py --case bounded --output /temporary/trial/project --receipt /temporary/trial/inputs.json
```

Use new paths for `status`, `domain` and `reserved`. Copy only runtime entrypoints,
references and resources to a sibling skill snapshot, excluding evals/tests.
Give a fresh independent actor its project, snapshot and designated observations
directory: "Use sdd-workflow-router and actually carry out REQUEST.md. Record reads,
commands, outcomes and stop reason in the observation directory."
Do not give it suspected defects, the comparison result or an intended route.

- Bounded: actually fix rejection of negative retries and add a faithful regression;
  original accepted inputs still work. Keep README/rules/request/notes unchanged.
  No Spec/Plan/card/checkpoint/handoff/view is needed by the supplied project.
  A route recommendation or an offer without repair fails the action request.
- Status: identify Linux evidence as supplied, retain mandatory Windows as NOT RUN,
  leave whole-task completion open and keep every project input byte unchanged.
  Do not generate a view or proposal because status was requested.
- Domain: identify concrete missing owner-controlled fee semantics; leave source
  and other inputs untouched. Do not invent a rate, generic reference implementation,
  fake approval or pass claim. A generic "need approval" without an input question fails.
- Reserved: surface the exact draft Plan and a usable scoped approval question,
  retaining READY_FOR_DESIGN_REVIEW and its actual baseline. Do not modify code/tests
  or claim approval just because the change is local.

Inspect actual trace and artifacts, not exact response phrasing or an outcome token.
For bounded old/new comparison run the same input in fresh actors with no model
setting override; retain if the baseline already handles the task well. Report
source/read-path bytes separately from real host-reported tokens/time; moving text
to references is not a measured efficiency gain. If RUN behavior/control changed,
also replay the existing contract-handoff clear/reserved/recovery protocol.

Keep original files, initial failures, environmental gaps and any evaluator intervention.
Single pilots establish scenario applicability, not human usability, all-host reliability
or superiority over another framework. The company novice/expert trial remains separate.
