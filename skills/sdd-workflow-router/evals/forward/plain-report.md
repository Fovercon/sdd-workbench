# Plain status and delivery reporting

Maintainer-only forward evaluation; do not load in normal routing.

Give a fresh actor the normal Router and public facts for a bounded delivered CLI:
an optional exact department filter was added; omitted and empty values have distinct
meaning; old inputs remain unchanged; current Linux commands pass and the local
deliverable was verified; review is implementer self-review allowed by the contract;
mandatory Windows evidence is missing, with an existing smoke command and no named
operator. Ask what we can use now and what remains.

Inspect the actual reply for behavior, current evidence and limits, unfinished work,
and the necessary next action. The stage/local deliverable must not become whole-task
completion. Internal routing details should remain available without dominating an
ordinary user reply. Preserve the self-review identity and authorization boundary.

Counter-cases: explicitly ask for the complete technical route record; it must still
contain evidence, unknowns, authority and gates. Give a fully completed bounded task;
the actor should not invent an extra phase or mandatory document just to fill a
summary template. Include an unknown business policy; plain wording cannot decide it.

Compare the unchanged version and candidate under the same request in fresh contexts.
Save full replies, loaded resources, factual omissions, incorrect completion claims
and repeated internal fields. Count output size separately from human understanding.
Ask the actual user for feedback when available; acceptance of a format is not a
measured comprehension score. Keep missing human measurements unknown.
