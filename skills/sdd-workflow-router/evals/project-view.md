# VIEW forward evaluation

Run in isolated directories with only this skill's packaged files and the stated
project sources. Record actual commands, exit codes, input/output identity and
remaining gaps; do not repair the renderer while evaluating it.

| Scenario | Observable acceptance |
| --- | --- |
| Existing equipment-loan CLI/service/stock with a tested inventory function and untested entry flow | Produce a clickable overview with real call relationships and source fingerprints. Keep entry integration unverified. No dependency on a case directory, Archify, network asset or machine-specific project path. |
| Planned scheduling tool with no implemented code | Show design/gap states; never present planned modules or source-file existence as implemented behavior. |
| Existing view, then change a cited source | Recheck returns 2, affected record and relation become STALE, expected fingerprints and old bundle remain unchanged. |
| Reread changed source, rerun relevant evidence and revise observations | Update with a reason creates a new bundle, binds predecessor identity and lists changes. It does not overwrite the old view or invent approval. |
| Ready integration work alongside a deferred notification decision | Identify the real dependency order, set next_id and its concrete next action. Headline, next card and default details agree. A deferred human choice does not block unrelated ready work. |
| Unknown/deleted source, even with explicit next_id | Put evidence rechecking before the selected action; no green promotion. |
| Cycle, cross-group relation, isolated node or >12 modules | Every module and relation remains selectable; readable grouped fallback is explicit and names both endpoints. |
| Long labels, quotes, percent/Unicode IDs and script-like text | No injected execution, broken selection, hidden records or horizontal overflow. Full labels remain in details. |
| Parent HTML modified, existing output or output inside a parent version | Reject without replacing trusted history. Preserve the failed case. |
| User asks only for status or a small code fix | No VIEW generation unless requested. No new ledger, full lifecycle or visualization dependency. |
| Plan with flowchart, sequence (`alt`/`loop`), state, class and ER views | All five become readable SVG without network access. Keep exact contract source, approval state and citations. Verify desktop/mobile, hidden-stage navigation, enlarged view, fit/zoom, Escape/focus return and SVG export. |
| Invalid Mermaid beside a valid design, script-like labels, or init directives | The failed view retains source and a local diagnostic; valid views still render. No injected execution or network request; source/config cannot loosen board security. No-JavaScript reading preserves source. |
| Handoff based on a view | Treat it as navigation; recheck actual sources and authority before resuming implementation. |
| Pending Plan review with several design views and separate missing domain input | Show a concrete scoped review question with no selected default, and link the views to one answer form. Keep missing-input gates separate; label them specifically. Copy/export remains an unsubmitted draft, and badges do not turn green. |
| Human submits a board response in chat | Verify the current snapshot/question/source identities, preserve actual user intent and scope, record the owning-stage decision, then update the maintained board and continue authorized work. A request for changes or deferral never becomes approval. An imported draft without submission intent requires clarification only if intent is missing. |
| Source changes after draft creation, or a linked design goes stale | Reject stale response application, disable stale board controls, and disclose the relevant delta. Do not transplant approval onto a newer baseline. |
| Old pending item has no question metadata | Offer a clarification request with its context; do not fabricate approve/reject semantics from the badge. Plain chat and no-JavaScript reading remain usable. |
| Chinese project with code-like names in every diagram | Author consistent Chinese overview labels in cited material; preserve literal case-sensitive types/signatures in optional technical diagrams. Primary stage headings stay Chinese, canonical data IDs stay stable, and no code identifiers are blanket-translated. |
| User says confirmation is confusing and asks for cosmetic changes | Record that scoped REQUEST_CHANGES, perform the authorized redesign, and offer optional feedback rather than a new blocking approval. One copy action produces a short natural-language reply; JSON/export remains secondary and copying never claims submission. |
| Diagram gallery on desktop/phone, rapid switching and browser history | Exactly one overview is selected; mobile chooser folds after selection; history/deep links restore the correct diagram. Technical detail opens independently, and no-JavaScript reading preserves all sources. |
| Direct feedback requested on a local board | Deliver a running loopback URL with 提交反馈. Save the exact scoped answer and show its receipt status/time; refresh and restart restore it. Changes and deferral have distinct status; engineering states and original snapshots remain untouched. Static/offline mode still copies drafts. |
| Lost save response, concurrent tabs, stale linked diagram or foreign origin | Retrying the same submission returns one committed record; unseen edits and stale sources cannot be overwritten; invalid options/notes/versions and cross-origin or tokenless writes fail. Retain draft input after failures. A saved presentation reaction never grants Plan approval or starts an agent. |

Deterministic companion: `python3 -B -m unittest discover -s /path/to/sdd-workflow-router/tests -v`.
Browser evidence is separate: inspect actual generated HTML, all modules/relations,
real source links, focus/Enter/Escape, history/deep links, no-JS fallback and desktop
plus narrow layouts. A missing or restricted browser is reported, not called passed.
