# Record evidence where the first check is saved

Use this maintainer protocol with the two-slice FEATURE case from the
[Router pilot protocol](../../../sdd-workflow-router/evals/forward/pilot.md).
Freeze a pre-change runtime and a candidate runtime. Give both actors the
same initial project, permissions, prompt and ordinary tools. Start five
fresh conversations per version. Keep scorer instructions and previous
actors' files outside the actor's view.

## Observe the producer

Before changing instructions, inspect the original version's tool results
and documents. Identify each slice's actual RED, first focused GREEN and
regression by invocation, subcommand and tested source. A setup error and
the later behavioral failure are separate observations.

For each version, inspect the earliest persistent write of every observation
and the delivered task table, receipt and chronological trace.

- Attribute details to the original check, including command, result, source
  and tests. A prescribed card command is planned. A later invocation is new
  evidence even when command and test count match.
- Count both physical file locations and full restatements within one file.
  Count a resolvable pointer as a pointer. Missing results, source identity,
  original failures or required trace events remain evidence gaps.
- When an out-of-slice edit is reverted and tested again, distinguish the
  first GREEN from the corrected closure check. A later matching source hash
  does not identify which test revision or invocation established closure.
- Reopen cited sections after advancing to S02. Check actual heading anchors
  and retained card revisions. A filename, fragment string or copied hash
  alone does not establish that the record can be retrieved.
- Preserve the project's required independent receipts, inline fields and
  chronological results. Cover a separately required self-contained receipt
  and an existing whole-file hash reference in focused controls.
- Inspect actual product behavior, repairs, final examples, delivery and all
  observed writes. A smaller document can still contain an unsupported claim.
- Read the first persisted receipt and every replacement. Record any GREEN
  or completion claim written before its checks actually ran, even if the
  actor later removes it and obtains a genuine pass. Establish chronology
  from native tool events and cross-check authored timestamps against them.

## Ask a fresh recipient

Preselect project slots 1–3 per version before running. Preserve a failed or
incomplete slot under its original ID. Use two fresh readers per selected
project, with the same reader skill runtime and prompt in both versions.
Give readers the final actor-written project and its original contracts
with read-only authority.
Ask them to locate S01's consumed card, original failure, first GREEN and
tested source, then assess whether those results apply to the current tree.

Readers should identify broken references, retained original evidence and
later repairs separately. Observe their successful reads, extra searches,
out-of-scope read attempts and actual current checks. Keep actor documents
intact. If the producer lost the card or source
identity, record the reader's inability to verify it.

## Decide retention

Freeze the primary measure and limits before running the candidate. Report
duplicate detail, evidence retrieval, product correctness and permissions
alongside whole-flow requests, input/cache/output, time and record-write
activity. A reduction in file count does not establish total cost savings.
Run the standard regression on the exact candidate and report unresolved
gates. Retain or drop the method according to the declared criteria.
