# 可选的检查记录与引用校验

本轮新增 `sdd-implement-slice/scripts/evidence.py`。需要保留可复查的检查证据时，可以选择这两个动作。

- `record` 实际执行一条命令，在获准追加的日志中保存真实输出、子进程退出状态、源文件及测试文件的前后摘要，并返回可粘贴的相对 Markdown 链接。同一日志内不能重复使用编号。
- `verify` 从已保存的任务表或回执读取实际链接，检查文件、锚点、记录完整性及摘要。历史记录是否完整和当前源码是否变化分别报告。

记录成功与测试通过有独立字段。超时、中断及未封口的记录保留为不完整。调用者仍需遵守项目现有的写入权限、自足回执和整文件冻结要求。记录器不隔离被执行命令的副作用。[调用方式及输出解释](../../skills/sdd-implement-slice/references/evidence-records.md)

## 为什么保留为可选能力

候选 `157ab01` 试过让每一步检查都通过记录器。与 `04980ff` 各跑五个新的双切片项目，得到以下结果。

| 联合候选的五对完整开发 | 对照 | 强制接入候选 |
|---|---:|---:|
| 额外的完整命令及结果段落 | 22 | 14 |
| 六项切片检查各只详记一次的项目 | 0/5 | 3/5 |
| 有失效历史片段引用的项目 | 3/5 | 0/5 |
| 任务源码通过独立产品检查 | 5/5 | 5/5 |
| 正确的可重放交付示例 | 19/20 | 19/20 |
| 全程累计输入 token，含缓存 | 22,895,997 | 24,795,332 |
| 主要记录的实际写入调用 | 59 | 125 |

重复段落减少约 36%，没有达到预设的至少减半目标。两组产物仍把同一检查写进阶段总结和回执，候选还有十处同文件内的重述。强制接入的成本数据也不支持全流程降本。

工具本身取得了直接证据。候选两片的全部 30 项核心检查都由真实子进程执行，命令退出、源码和测试摘要与独立宿主观察吻合。65 个封存记录逐一核对，全部文档中的 166 处生成引用均能定位。五张任务表可以直接或经回执到达全部核心检查。

预选两版各三个最终项目，每份交给两个新会话。候选读者 6/6 找回旧卡与真实 RED/GREEN，对照分别为 4/6 和 5/6。候选读者累计输入中位数约为对照的 2.21 倍。读者都使用原版运行时，衡量的是直接阅读自然交付物的成本。该结果属于上述联合候选，不能代替最终可选入口的效果。

据此，可选入口以 `d500558` 做功能验收，再以 `bec823f`、`1623c06` 修复解析器缺陷。本轮提供记录器、引用校验和按需调用方式，按项目允许的记录格式选择。原始写入错误、修复和未达目标的结果均保留。

## 可选能力的功能验收

明确选择使用工具的五个新会话在 `d500558` 上运行。两片的 30 项核心检查均直接执行 Python 单元测试，宿主核对了同一进程的退出状态，其中十次 RED 退出 1，二十次 GREEN 与回归退出 0。总计 62 个封存记录的实际命令、退出和所测版本一致，262 处生成链接均可定位。该验证支持工具功能，不推断默认采用率或成本收益。

五份源码都通过独立产品检查。交付示例 15/16 正确，一份把 2/3 写成 33%。三个项目向授权范围之外的隔离临时目录写了文件。两个项目还有五处手写的行内代码卡片指针需人工定位。这些代码文本没有 Markdown 链接语法，当前 `verify` 检查实际 Markdown 引用时不会检查它们。

另做三份指定自足格式及旧回执整文件冻结的项目。三个旧回执均保持原字节，18 项初始切片记录与真实执行吻合。六份自足回执有五份完整，一份追加修复只写了命令摘要，其交付示例还把 75% 写成 50%。上述结果保留为格式遵从方面的实际限制。

## 验证如何区分有效和失效

28 项实命令回归覆盖实际非零退出、原始输出还原、重复编号、协作锁、中断、路径替换、源文件变化、相对链接和坏锚点。独立复核发现的 SIGTERM 子进程继续运行和引用式 Markdown 链接漏检均已修复。原生 Windows 行为留待跨平台 CI 核验。

另对自然产物的三个独立副本各改一处。错误锚点被报为缺失，截断结束记录被报为不完整，源码变化保留完整的历史记录并标明当前文件已变。原作文件保持原样。

兼容性产物暴露了嵌套列表续行被当作代码、漏检三条真实链接的问题。修复提交 `bec823f` 按 Markdown 容器处理列表和段落续行，也保留真正的缩进代码、围栏及引用块边界。用该版代码重放八项目、90 份 Markdown，独立对照识别率由 333/336 补齐为 336/336。两次新的只读验证分别确认原件八条引用有效，以及单字符坏锚点准确返回退出码 2。前述五次写作和三次格式验收的原始记录仍署名 `d500558`。

收尾审查又发现，只给链接标题加反引号就可能漏掉整个引用。`1623c06` 保留标题及引用定义的原始身份，仅屏蔽真正代码示例中的括号，并正确区分转义反引号。新增五项 CLI 回归均先复现失败再通过。常见标题和空标签可以检查，检测到未支持的链接写法则报 `UNSUPPORTED`，不再默默给出有效结论。校验器限定于文档说明的单行形式，未实现完整 Markdown 渲染器。

最终版本重放原八项目、90 份 Markdown，仍与独立 CommonMark 对照的 336/336 条链接完全相符。另取自然 S02 回执的两份一次性副本，一份仅将真实链接标题包为代码，另一份同时把该目标的 `v2` 改为 `v3`。原 trace、源码和测试逐字节相同。两个新只读会话实际运行最终工具，分别得到八条有效及七条有效加一条坏锚点，进程退出 0/2；没有写入或重跑历史检查。旧版对此两份材料都仅看到七条而误报有效。

前面三个候选的中途标准试次保留为已终止的实验，不给整轮成绩，也不混入最终候选的数据。初始布局测试有一次导出多带两个根目录文档，发现后封存该技术性错配，并以严格匹配的 78 文件运行时重新开始。

## 最终标准回归与保留结论

最终候选 `1623c06` 的标准回归为 `20261125T043238Z-standard`。211/211 个试次正常结束，包含 76 个触发用例和 135 个端到端试次，3,465 次工具调用与隔离执行逐项对齐，模型错误为零。触发用例答对 69/76，13 项门槛通过 9 项。普通完整技能组相对同批裸模型的总 token 比为 1.69，通过上限 3，任务平均分增加 0.0855。该轮未通过项如下。

| 最终标准回归的未过门槛 | 实测 | 要求 |
|---|---:|---:|
| 强制定向流程与裸模型的总 token 比 | 61.01 | ≤8 |
| 声明启发式标记 | 8 | 0 |
| 字面可追溯性 | 0.4924 | ≥0.8 |
| 可见验收与综合分的最大差 | 0.6 | ≤0.5 |

逐项复核八个声明标记，均有真实的本地检查通过，也都确有一项隐藏验收失败。五份明确限定了检查数量或独立探针，三份有范围宽泛的通过措辞。未发现捏造执行或声称隐藏套件通过。最大分差对应四个变更任务，可见测试全过、隐藏测试各为 2/3，但回复形式分为零，合成为 0.4，故门槛统计为 1−0.4=0.6。保留正式评分，不能直接把这两项解释成八次伪造或有意刷分。

所有会话显式使用注册模型 `deepseek/deepseek-flash`，后端修订未报告。最终轮按原生请求单计为 2,697 次模型请求、106,871,599 tokens，其中缓存读取为 101,372,800。客户端估价为 4.7723 美元，未经账单核验。冻结评测代码未变，并发从此前的 8 调至 16，不能将跨轮耗时差异算作方法收益。未接受新基线。

最终标准题面没有点名工具，两个定向试次自行尝试 `record` 共 25 次。三次缺日志目录或文件、一次争锁，均在执行检查前拒绝，后续重试成功。其余 21 次有真实检查子进程，封存记录与已返回的退出码逐项一致。其中 12 次还保留了完整原生 JSON 和链接，另九次由调用方转成简短文本而省略链接。完整三方回执只计前 12 次；未发现退出码与封存内容不一致。

解析器收尾前的 `bec823f` 另有完整回归 `20261125T040318Z-standard`，211/211 结束、10/13 门槛通过。该轮的自然完整技能组为裸模型的 1.83 倍用量，强制流程为 53.54 倍。标准题面没有点名新工具，一个试次自行记录 11 次实际子命令，另两个试次留下 7 次可唯一归属的链接校验。这些自然选择与明确选用工具的功能验收分开统计。该轮 12 个声明标记的逐项审阅也单独封存，不能混入最终八个标记。

最终 `1623c06` 的 421 项本地测试通过，分别为根目录 135、Router 178、context 108。打包、发布文档链接及五项 Node 检查通过。构建 ZIP 并在独立临时 home 实装后，记录器实际保存了退出 1 和退出 0 的两条命令；任务链接校验能区分旧源码已变、新源码匹配和坏锚点。未修改开发者的实际安装。

本轮保留可选工具及评测协议。强制接入未达重复减半和成本目标，未纳入默认步骤。失效 Markdown 引用现在可机械检查，手写代码指针、格式遵从、交付数字、授权范围以及强制流程成本仍有问题。它们不能由记录器成功或结构测试通过推定解决。
