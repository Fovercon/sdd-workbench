# 紧凑校验计数与省略范围评测

本轮处理上一轮的两项解释错误：把总引用数都当成执行记录数，把省略正常源码
字段说成省略整条记录。接口中的原数值并没有算错；本轮让展示直接给出分类与
实际省略信息。它不是新的执行记录器，也不改变校验步骤。

基线为 `2d6ff65`。第一版 `a06f714` 加入分布和静态省略规则；修订版 `c79111e`
保留分布、改为实际省略计数。两版候选的试次、兼容重放和标准结果分别保留。
最终保留修订版的可选展示改动到开发分支：实际省略量与真实输出一致，默认行为
和旧紧凑行兼容，不增加工作步骤。前向和最终标准均已完成，但没有证明原两类
误读率下降或整体降本；其余解释、权限和标准门槛失败照录，不标为发布就绪。

## 接口的实际变化

默认 JSON、命令退出码、记录器，以及旧紧凑模式的 `status/links_checked/links`
和每条记录都保持原值。修订版另外返回：

- `history_counts`：省略前全部引用/诊断行的状态分布，含重复引用，和等于总数。
- `omissions.LINK_OK.whole_rows`：本次实际省略的普通链接整行数。
- `omissions.RECORDED.whole_rows=0`：记录引用整行没有丢弃。
- `field_only_references`：仅省源码字段的记录引用次数；`fields` 列出那两字段，
  未发生字段投影时为空。

这些数都是引用出现次数，不是唯一命令或实际测试数。字段投影仍要求无记录到的
执行期变化且当前源码全部 MATCH；其他异常诊断和源码漂移细节保留，历史非零
退出码始终保留。非零退出本身不阻止健康源码字段的投影。

## 兼容和确定性证据

修订版在相同 15 个可丢弃夹具上各跑旧默认、新默认、旧紧凑、新紧凑，共 60 次
真实只读校验。默认 stdout/stderr 字节和所有退出码一致，旧紧凑字段/行相同。
分布与原完整输出一致；整行省略数、字段投影次数及字段名由实际行/键差独立核对。
重复引用照计，记录目标与退出码的原顺序保留。

覆盖历史失败、当前 CHANGED/MISSING、真实 UID1000/mode000 的 UNAVAILABLE、
执行期变化后恢复 MATCH、坏/缺失/歧义锚点、篡改/截断、无引用和顶层 ERROR。
每次前后路径、字节、权限一致，未观察到文件写入。固定 15 例没有 UNSUPPORTED，
该类型由 CLI 测试覆盖，不把它说成这批重放已测。

| 自然文档 | 完整输出 | 旧紧凑 | 修订版紧凑，字节 |
|---|---:|---:|---:|
| 当前记录正常 | 441 | 257 | 437 |
| 含历史漂移 | 3,181 | 1,650 | 1,847 |
| 含真实坏引用 | 1,389 | 1,410 | 1,563 |

本组元数据合计增加 2,359 字节，非 ERROR 每次增加 140–201 字节，ERROR 不增加。
这是可解释性开销，不能说整体更短或更省 token。坏引用夹具沿用真实 trace 历史
快照加同项目终态其他文件的混合构造，未宣称整树就是同一历史时点。

## 第一版为何继续修订

五个新对照和五个第一版定向读者，对原来的两类误读均为 5/5 正确。每份初始
上下文都明确提供完整指南和同两份真实 JSON；这与历史上未完整读指南的失败
情境不同。不能把候选通过当成原错误已经消除或可靠性提升。

较宽的六项理解标准为 3/5 → 4/5，包含当前/历史源码适用性等其他问题，不能
包装成原计数目标改善。第一版仍有人声称“全是 RECORDED 时两模式无差”，忘记
健康源码字段的投影。因此修订版用实际省略量替代静态规则，不再要求读者自行推导。

第一版原定 22 个试次均结束并封存。对照定向一份大输出使原生 bash 工具自动
创建两份临时日志，非模型显式重定向；项目/运行时未改不等于整场零写入。
自然接手完整原始输出取得为 5/6 → 6/6；正确摘要不能补足未实际返回的原始流。
自然组总 token 为 2,979,783 → 3,856,559，不能把校验调用减少说成接手降本。

第一版标准轮 `20261126T111649Z-standard` 在决定修订后停止：113 槽完成、
16 槽运行中中止、82 槽未启动，没有完整门值报告。已用原生用量单计为 1,174 次
请求、21,110,425 tokens，Pi 估价 1.7563 美元，未经账单核验；其中包含中止槽
的已报告用量。所属进程与监控已清理，没有重抽或把中止记成模型行为失败。

将这些差异当成产品缺陷或本次元数据退化。最大 0.6 分差还包含回复评分权重，
不是简单的可见/隐藏测试通过率差。

实际采样至少见 213 次 summary 进程，其中 104 份完整 JSON 能唯一对应原生返回，

这是形状/归属核验，不是同次完整模式的独立反事实，也不是唯一执行次数或理解
成功率。部分输出与归属不明的输出不算完整；语义兼容由前述 15 案例重放支持。
