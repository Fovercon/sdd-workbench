## 本轮需求边界

- 大众用户能从实际目标进入，不以掌握 12 个名称或审批术语为前提。
- 流程深度与风险匹配：明确局部工作不补无用材料，高后果/含义不明任务不以“小”绕过关卡。
- 保留职责、显式保留的批准、领域输入、用户工作区和真实证据的边界。
- 差异化声明必须区分已实现机制、已跑样本和待证优势。
- 外部 agent/专家的意见能复现、归属、复验；作者与 reviewer 的身份不混淆。

本轮不承诺可靠性比例、时间/Token 收益或全平台业务认证。这些需要真实试点与对照数据。
用户已明确确认：公司首批试点以研发工程师为主。典型业务、主要 agent/模型、数据和审批
政策仍待提供；不据此编造企业规则。

## 已确认的首批人群与验证优先级

依据本轮用户对试点人群的明确回复，后续易用性验证先围绕研发日常工作安排，以下为
待执行的任务组合，不是已取得的使用结果：

| 优先场景 | 需要观察的结果 |
|---|---|
| 已知局部 bug 与回归 | 能实际完成修复和验证；不反复索取已有授权，不制造不必要的合同/看板 |
| 存量代码中的小功能 | 核对已有规则和实现边界，补齐必要验收后交付；不把既有代码误当产品决定 |
| 已批准需求的变更 | 识别受影响合同、实现与旧证据，保留历史，不静默重写批准内容 |
| 代码评审与修复交接 | 区分有无规格基线，问题可复现；明确修复授权可继续，只评审则不越界 |
| 中断续接与交付核对 | 核对来源、脏工作区及旧验证身份；保护用户修改，过期结果不冒充当前通过 |

人员覆盖按“第一次使用本套件的研发工程师”和“已熟悉本套件的研发工程师”分别记录，
不把编程经验与套件熟悉度混为一谈。真实人员数量、团队构成和推广规模尚未决定。
Agent 演练继续用于方法回归，不能替代上述真人易用性验证。产品、测试等其他角色保留
在后续覆盖范围，不因首批以研发为主就宣称已验证。

## 第一步执行卡

**目标**：安装后用自然语言提出工作即可得到最小适用处理；把操作分流和硬边界留在入口，
大部分诊断规则只在真正诊断/选阶段时读取。版本基线为 v0.2.1。

改动：README 的用户旅程；`docs/QUICKSTART.md`；Router SKILL.md 与现有 routing-model 的
职责重新分配；维护者评测输入与回归；本计划和 reviewer 包。保持 12 个技能及其名称，
不修改任何下游阶段的产品/授权合同、安装器、发布资产和 Mermaid。

| ID | 可观察验收 | 验证 |
|---|---|---|
| S1-A | 用户能找到小改动、新功能、评审、状态和看板的自然语言起点、预期结果与适用边界 | 用户指南核对、独立 reviewer 任务 |
| S1-B | 入口轻量识别可直接处理的任务，不因缺 Spec/Plan 强制建全套文件；用户已经授权的局部工作真正完成 | 同输入旧/新实际 actor；检查功能、测试、原文件与新增产物，不只看 outcome 字样 |
| S1-C | 状态查询仅报告当前事实/缺失证据；不生成看板、合同或实现 | 独立只读反例，核对全部输入哈希 |
| S1-D | 支付/费率等缺失核心语义以及用户保留审批不被轻量路径绕过 | 具体输入/批准问题与源文件保护的反例；不编造语义 |
| S1-E | RUN 的完整控制、恢复、结果语义与领域扩展降级仍可到达；没有删除或放宽其规则 | 细节归属表、所有相对链接、原有包/Router/浏览器回归；改变 RUN 控制则额外按原 forward 协议演练 |
| S1-F | Router 入口的实际 bytes 小于原 17,537；新旧内容和选路行为均可检查 | 冻结原文/新文与指纹，报告 bytes/路径；不把移到 reference 的字节说成 Token/时间节省 |

范围判定：此处是在维护已声明的按风险缩放和渐进加载规则；局部通路前置是需要 forward
核验的方法变化。原 RUN 控制内容保持，入口职责整理不能冒充完全机械改写。

失败处理：若局部通路漏掉领域/批准/工作区保护，或只报告路线不完成已授权任务，回退该
通路并修正；若压缩造成规则丢失，恢复原文或显式归还给已有归属 reference 后重验。
通过标准不是字数最少，更不是“测试多就能推广”。

交付形态：本地可审查分支和 diff、文档、运行结果。不在这一步推送/发布新版本。
测试发行时只在临时副本使用独立 prerelease 身份，不替换 v0.2.1 既有内容。
