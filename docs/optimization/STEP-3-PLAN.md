## 事实与范围分析

- FACT：README 的更新入口直接执行 install，没有展示每个技能、已有编辑、接管与删除的零写入预览。
- FACT：AGENTS 要求安装器只管理记录目录、保留用户编辑/备份、先恢复事务再写。
- FACT：receipt 先判断 exists 再判断 symlink，失效回执链接会被当成未安装；ensure_idle 的 exists 忽略失效 pending 链接；JSON 顶层为 list/null 会导致未处理的 AttributeError。
- PROPOSAL：新增 `install --dry-run`，逐目标展示操作、逐技能差异/身份、阻塞和 force/adopt 意图，不生成目录、锁、缓存或备份；正式执行仍重新预检。
- CORRECTION：拒绝损坏/外来回执与所有事务链接，不把它们解释为空状态。有效旧回执和事务继续兼容。

主要归属 SPEC：增加可观察的预览能力，作为现有授权优化的具体实现选择，非逐条人工审过的产品批准。
传播 FLOW_FORWARD，边界/验收在本卡中冻结；已有所有权与恢复合同不变，其违例为附属 IMPLEMENT 修复。
依赖：CLI -> 现有 preflight -> 只读差异 -> JSON/退出码 -> 运维说明与真实子进程演练。

技术约定：预览复用正式 preflight，不另建放宽规则；预览不持锁，所以是瞬时观察，不是
可执行批准令牌或并发安全承诺。正式 install 的锁、重验、备份和恢复仍为最终写入防线。
JSON 为新增输出形状，既有 install/status/rollback/recover 的成功形状不变。预览退出
0 表示全部目标当前可预检，1 表示阻塞/失败；没有提前执行任何安装。

影响：安装器/doctor 共用回执解析需 REVERIFY；CLI 兼容、旧包元数据、包输入与发布检查
需 REVERIFY；12 个技能方法、Router/UI/Mermaid 为 UNCHANGED（本轮无指令/页面行为改动）。
不以本轮测试更新六平台模型/真人试点结论。顺序：新回归 RED -> 最小代码修复/预览 ->
CLI 运维演练 -> 必需全量回归/临时发行检查 -> 自审与本地证据归档。

自审追加事实：rollback 从备份记录生成 targets 前未验证目录名，受控篡改可使 targets
含 ../outside；这是违反既有所有权边界的 IMPLEMENT 缺陷。恢复路径已有名称约束，
改为两条路径共用严格事务校验，不改变合法回退语义。首次 78 项通过发生在发现它之前，
不能作为该缺陷已覆盖的证据；新增用例后另行运行完整回归。
