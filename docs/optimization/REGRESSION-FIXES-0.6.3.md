# 0.6.3 维护评测器修复

本批只修评测器和未来评测输入的合同缺口,不增加技能流程规则。维护框架从旧维护
工作树的152份源码/夹具按哈希复制到开发分支;旧目录、历史试次及安装未改。
该框架在打包白名单之外,不作为0.6.3插件输入。实验目录为
`regression-fixes-063-wqt_8mz3`。

## 可见测试的实际路径

旧实现把新建/变更测试复制到一个平面 `visible-tests` 目录,导致按 `__file__`
推导的CLI根目录变化,同名测试相互覆盖,并在原提交目录执行其写入。

修复后仅在可丢弃的项目副本中执行已选测试,保留原相对路径、相邻夹具和包导入。
内部绝对/相对软链接重映射到副本内部,外部和循环软链接明确抛 `EVALUATOR_ERROR`。
初版副本保留绝对链接仍会写穿原工程,该审查反例已另补三项RED/GREEN并修复。
副本不是OS沙箱,没有声称能隔离任意Python中故意硬编码的外部绝对写入;执行
历史模型产生的测试时仍需独立的操作系统隔离,不能只靠目录复制。

新回归覆盖CLI/夹具相对路径、两份同名文件、包相对导入、不导入未改起始测试、
普通相对写入不改提交、内部绝对链接写入不改提交、外部/循环链接显式失败。
旧行为先出现CLI失败、总数1而非2、写回原项目三类失败;修订副本的包导入和
软链接反例也分别保留首错。最终八项均通过。

## 未来公开合同与隐藏检查一致

text-diff 原“末尾无多余空行”未区分字符串API和CLI尾换行。新的公开FR-004明确
`render` 不含尾换行,空序列返回空串;FR-005明确CLI对非空结果追加一个换行,
空结果不输出。oracle和隐藏render期望同步,既有CLI非空stdout期望保留。独立
测试先见旧oracle带尾换行而失败,修复后render/CLI两项均过。

change-request 原公开输入只列五次重试间隔和上限,没有定义超预算查询;旧hidden和
oracle却要求默认对象 `delay_before(6)/(9)` 返回30。未来 entry_prompt 明确纯
退避值查询接受任意正整数,查询不触发或允许第六次实际重试,预算仍为五次、总
尝试为六次。directed只沿用原前缀加同份entry。原hidden的6/9期望未改。
维护者新选择的合同同时暴露oracle对极大正整数的指数溢出,已先见真实OverflowError,
再在封顶序号提前返回30;公开示例与oracle查询、百万序号查询均通过。

历史actor没有收到这些新增明确文字。原标准九项声明标记、cap边界差异和9/13
门值均保留,不能使用今天的prompt把当时的边界处理说成违反已明示合同。未来
新模型运行按新语料身份记录,不与旧分直接相减来声称技能改善。

## 原生模型用量去重

旧parser将assistant `message_end.message.usage`和随后镜像的
`turn_end.message.usage`都累加,还把非assistant样例用量计入。现在逐真实assistant
请求计一次;仅该轮没有message_end用量时才保留turn_end旧格式回退。单个result
仅在全流无其他可读用量时回退,不重复加入摘要。缓存读写计入total,reasoning
不另加。未知/缺失用量保留未分类数及 `complete=false`,成本汇总和比率为null,
不伪造零用量。没有按usage数值去重,因此两个不同请求即使数值相同也都计入。

同一旧标准 `20261126T113153Z-standard` 的211份原始事件只读重解析,没有跑模型
或产品测试。每份都与独立逐assistant message_end累加相符,完整用量211/211:

| 同一批原始事件 | 旧parser | 修复后单计 |
|---|---:|---:|
| 用量事件 | 5,674 | 2,837 |
| 输入 | 5,869,920 | 2,934,960 |
| 缓存读取 | 217,412,352 | 108,706,176 |
| 缓存写入 | 0 | 0 |
| 输出 | 5,500,504 | 2,750,252 |
| 总token | 228,782,776 | 114,391,388 |

这是统计修正,没有节省实际请求或费用。例 `text-diff/baseline/t2` 的九个
message_end和九个turn_end完整message逐对相同:input 9,300→4,650、output
13,294→6,647、cacheRead 97,280→48,640。原报告已经另列正确单计114,391,388,
本批没有把正式旧报告改写成新分。

## 检查及后续重放边界

离线全套自检98项通过,包括九个任务的oracle/起始树门槛和框架不入发行包检查。
原维护快照152份文件哈希复验未变。RED/GREEN、源码快照、同211流新旧比较和
旧文件复验分别保留在实验目录,没有新模型费用或接受新基线。

若需重评分,必须新建派生实验目录,冻结原slots、events、提交树和两版评分源码
哈希;原目录只读。可见测试在OS隔离中运行保留原布局的副本,隐藏检查在另一独立
隔离进程运行,不得让actor测试拿到隐藏目录。离线比较布局、用量与render口径的
变化分别报告,原合同不明项保留人工说明。新公开prompt不回注旧槽位,不覆盖
result/report/索引或accepted。完整前向与标准评测若再次跑新actor,须另记新语料
身份、模型和用量;离线重评分不能伪称新模型评测已通过。
