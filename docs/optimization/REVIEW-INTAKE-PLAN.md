# 第三步补充：多人审查的证据入口

接续用户“继续优化”，补 QA-02 的工程部分。公司推广批准、审查 owner、身份认证、支持
系统选择和模型政策不在本轮代决；不建立在线平台、数据库或强制所有小任务填写表单。

FACT：现有 REVIEW-KIT 已要求固定版本、原始事实、去重保留来源和复验，但只有文字模板。
PROPOSAL：新增 stdlib CLI，生成可移植候选指纹和草稿，核对显式报告及其证据文件，汇总
发现/复现/修复/复验声明，标记过期与矛盾；原始报告只读，不执行命令、不投票、不自动关闭。
归属 SPEC（授权优化范围内的具体技术能力），复用现有审查语义，不声称人类逐条批准此卡。

| ID | 必须观察 | 回归 |
|---|---|---|
| R-1 | 候选身份包含所有发行输入（含未跟踪文件），移位复制不改变指纹；声明版本不能代替字节身份 | 两个临时完整源、未跟踪工具修改、真实 CLI 快照 |
| R-2 | 草稿/已提交、自述身份/上下文、人工/agent 与作者关系分别记录；不同 ID 不等于独立审查 | 草稿不计正式结论；未知元数据不伪造 |
| R-3 | 证据相对路径和 SHA256 对应真实普通文件；不跟随链接/越界、读取设备或执行记录中的命令 | 篡改、缺失、../、绝对路径、符号链接、可执行恶意字符串；全树快照零写入 |
| R-4 | 复验绑定它自己的精确候选；当前失败优先保持失败，与当前通过同时存在时标争议；旧通过不续期 | 多报告、版本变化、同版本不同字节、通过/失败冲突 |
| R-5 | 显式关联目标、去重建议保留所有来源；重复 ID/未知引用/重复 JSON key 拒绝；不按人数投票或代公司关闭 | 乱序输入稳定、重复/缺失引用、矛盾与自检反例 |
| R-6 | 实际报告/候选清单不进入发行包；工具和合成测试可以发行 | 正向包检查、运行数据在 docs/tools 下拒绝，临时 ZIP 解压复跑 |

实现边界：只读 snapshot/new/evidence/check 四种命令；输出到 stdout，保存须调用者显式
重定向。只读 package 正向输入及显式报告旁 evidence/ 文件，不读账号/模型配置、不联网。
快照范围为 RELEASE_INPUTS，CI/忽略文件不在这个指纹内；完整工作树审查仍按 REVIEW-KIT。
报告中的命令、结论、身份和 fresh context 都是声明；哈希匹配只证明本次读到的字节。
check 退出 0 只表示格式/引用/证据匹配，不表示发现关闭、实现收敛或可发布。

保持 12 个技能及现有本机反馈 UI 的协议/行为不变。本轮实际反馈文件使用 .eval-artifacts
或包输入之外的目录；package 检查拒绝识别到的审查运行数据，不产生实际反馈数据库。
顺序：合成输入/反例 -> CLI 和包隔离 -> 用户指南 -> 全量/相关浏览器回归 -> 临时发行复验。
