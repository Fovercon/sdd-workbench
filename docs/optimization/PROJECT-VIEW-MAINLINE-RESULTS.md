# 项目总览与需求—切片—验收主线优化结果

日期：2026-10-26。范围/授权见 [本轮契约](PROJECT-VIEW-MAINLINE.md)。
本轮完成本地实现和验证；版本仍为 v0.3.0，未提交、推送、发布或更改 live skills。

## 可用行为

- 项目总览：目标、范围内/范围外、所列需求数、完成切片数、验证覆盖、受阻项与下一步。
- 需求规格：直接展示可观察验收条件，逐验项显示已有通过记录/待补验证，连接切片与运行证据。
- 任务拆分：TODO / DOING / BLOCKED / DONE 四列，显示真实前置依赖和阻塞原因；记录完成但来源失效时保留状态并警示。
- 对照验收：需求 → 切片 → 实现文件 → 验证结果 → 缺口。状态、结果与批准含义分开；不计算整体“完成百分比”。
- 保留设计图库、代码/功能双向导航、来源指纹、不可覆盖版本、本地反馈、无 JavaScript 阅读和旧格式兼容。

数据入口是已有观察项上的可选 `work` 扩展。没有结构化记录时不从文字推断进度。
逐验项关联通过 `acceptance_refs` 指向该版需求验收条件的序号；字段缺失是可见缺口。
来源变化向关联切片和验证传播，返回上游阶段会撤回下游覆盖判断。

## 发现及修正

1. Chrome 复现：从需求进入切片再回到需求，浏览器后退可能保留错误详情。
   原因是手动选择推入历史后未同步已处理 hash；修复后加入 Unicode、刷新、后退和恢复初始总览回归。
2. 第一次新上下文 Pi 试验指出 R1 的第二个验收条件未被验证，但旧候选只按需求/切片关联仍显示 1/3 覆盖。
   原始运行和页面保留。补上逐验项模型和可见缺口后，再以相同原始材料运行新上下文：R1 的严格匹配有通过记录、未命中提示待补验证，整体为 0/3。
   第二次生成的 JSON 未由控制方代修；原始材料哈希不变，候选 runtime 与最终实现一致。
