范围与可观察验收见 [REVIEW-INTAKE-PLAN.md](REVIEW-INTAKE-PLAN.md)。

## 已实现与边界

- `tools/review.py` 提供 snapshot/new/evidence/check：固定发行输入身份，生成草稿，核对
  普通证据文件，汇总明确列出的报告与跟进。全程只读，不执行任意命令或写原报告。
- 草稿不计正式结论；保留报告 SHA、候选、期望依据、事实、步骤、证据、身份/上下文声明。
  同一报告人不等于实现作者，不同 ID 不等于独立；工具不认证身份或判断日志真实语义。
- 当前候选通过/失败同时存在时标 DISPUTED；旧通过标 STALE_RECHECK；保留所有发现及
  重复/拒绝建议，没有投票、自动合并、自动关闭或批准发布。
- package 检查隔离实际报告/候选清单，避免把多人反馈当成可复用 skills 内容一起发行。
  [用户指南](../REVIEW-FEEDBACK.md)明确工具只用于正式多人审查，普通小任务不增加门槛。

| 发行隔离 | 默认报告后缀、改名 JSON/TXT、UTF-16 的其他扩展名均拒绝进入发行输入 |

| Router / Node adapter | 112 / 4 项通过 |

| 临时发行 | 仅临时副本使用 0.2.2-dev.8；两次 ZIP 一致、清单和解压检查通过；解压版完整 CLI 的当前/过期/争议与安装预览、六目标安装、doctor 通过 |

自审纠正两点：一是把同一发现的提交者与实现作者分开记录；二是初版包隔离只判断 .json，
新增 RED 复现改名 .txt/其他编码绕过后，改为核对已知格式内容标记，保留原始失败。
这些只是已知审查格式的隔离，不是任意私有材料的自动识别或脱敏。

合成回归不是其他 agents/专家的真实意见，也不能代表真人易用性测试。没有执行远端 CI 的
Windows/Linux/Python 版本矩阵，也没有增加六宿主/模型或竞品比较结论；所有实际运行只用
临时源码和目录。没有从本轮确定性结果推导方法行为成功率或独立审查认证。
