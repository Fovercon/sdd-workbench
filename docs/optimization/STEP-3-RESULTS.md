## 改动与实际缺陷

- 新增 `install --dry-run`：沿用正式 preflight，输出完整检查源包指纹、逐目标当前/目标
  版本、逐技能操作与文件差异、接管/force 请求和阻塞。一个目标阻塞仍展示其他目标；
  预览不创建目录、锁、字节码缓存或备份。正式写入重新预检和加锁，不消费“预览令牌”。
- 修正失效 receipt 链接被当成未安装、失效 pending 链接被忽略的问题；坏 JSON 顶层
  list/null 改为明确失败，拒绝外来套件、无效版本及无效指纹回执。有效历史格式不迁移。
- 提供[维护指南](../OPERATIONS.md)，区分 Python/Skills/原生插件的管理边界，串起诊断、
  预览、执行、状态、真实宿主发现和故障交接，说明回退个人编辑后的 changed 状态。
- 保留完整 RED：旧代码对失效链接未阻塞，外来套件回执会被接受，list/null 导致 traceback；
  新增预览尚不存在。先记录失败，再增加实现和护栏，没有以降低断言完成测试。
- 自审进一步发现 rollback 没有复用 recover 的目录名校验，受控篡改备份记录可通过
  ../outside 越出技能目录。新增 RED 在临时环境复现，修复为恢复/回退共用事务校验；
  回退现在同时核对目标、事务身份、目录名、前后指纹映射与当前回执，错误记录不产生
  目标改动。初次 78 项通过仍保留为发现前证据，不能冒充已覆盖此缺陷。

测试只覆盖本地 Python 3.11 环境；本轮未执行远端 CI 的 Windows/Linux/Python 多版本
矩阵。没有 UI 改动，未重复浏览器/原生模型试跑，既有证据不被包装为本轮新结果。
临时发行身份不代表发布计划，实际 plugin.json 和已发布标签未改为该版本。

真实子进程通过测试 harness 注入 `os._exit`，产品没有增加故障开关：

1. 六目标升级中途，Codex 已完成而 Hermes 替换中断；status/预览识别 pending，恢复 Hermes
   到操作前版本，再执行全量更新，最终六目标一致；无关用户技能保留。
2. receipt 已提交但 pending 清理前退出，recover 保留已完整提交的新版本。
3. 中断后又有用户编辑，recover 阻塞且不删除编辑；fixture owner 显式保存那份合成编辑后
   再恢复，保留失败记录和原备份。
4. force 更新把原编辑写入备份，CLI rollback 恢复原字节；旧回执继续列出 changed，不能
   将保全的个人编辑冒充干净官方技能。

本轮所有运行仅使用临时 source/profile。额外观察类回归覆盖仅元数据升级仍会重装、
曾管理技能的删除、同字节目录的接管、不能接管的符号链接、预览后再编辑仍阻塞，以及
多目标预览报告。完整字节/mtime/link 快照包括运行源，CLI 特意不加 -B 检验缓存零写入。
