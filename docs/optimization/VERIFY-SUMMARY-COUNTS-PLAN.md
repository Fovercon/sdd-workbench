# 紧凑校验计数与省略范围计划

基线 `2d6ff65`。上一轮一个真实接手者把总计 18 次引用误称为 18 条执行记录，
实际为八条 RECORDED 引用和十条省略的 LINK_OK；还误称当前 MATCH 的整条记录被
丢弃。旧指南已有解释，但该读者没有完整读取指南的证据，读源码后仍然误述。

## 最小设计

- 保留默认 verify、退出码、记录器和现有紧凑字段/行。最终修订版在紧凑输出中
  增加 `history_counts` 与实际 `omissions`，不新增工具、依赖或工作步骤。
- 分布从省略前的全部引用/诊断行计算，含重复引用；总数等于分布之和。任何
  RECORDED 目标/真实退出码保持原顺序，分布不能当唯一调用次数。
- 实际省略信息明说 LINK_OK 省整行、RECORDED 不省整行。字段投影仍仅在无记录到
  的执行期变化且当前全部源码 MATCH 时省 `source_changes` 与 `sources` 两字段。
- 元数据会增加返回字节。本轮优先检查理解准确性，不预设更短或全程降本。

## 实施与验证

1. 先冻结旧真实 JSON、项目、指南、模型配置和固定试次。定向五个新对照、五个
   新候选明确测 API+指南理解；问题不提供正确数字。旧版五次若已全对，不声称
   观察到行为改善。另用相同旧项目 t1–t3 各两个读者/版，共十二次自然接手。
2. 先写失败 CLI 检查：状态分布、重复引用、全普通链接、混合错误、空文档；
   声明的省略字段与真实键差一致。保留现有字段/行和默认 JSON、退出码、零写入。
3. 在既有投影循环累加分布和实际投影次数；同步既有指南，不增加主文步骤。
4. 用可丢弃真实夹具及坏/漂移/不完整/无引用/错误案例比较默认逐字节等价、旧
   紧凑字段和行一致、新分布恒等式、全部异常及非零退出保留、实际字节与无写入。
5. 独立审查后冻结精确候选。完成上述前向与最终 211 标准回归；跑全套本地
   Python/Router/context/Node、打包、文档和临时安装，不改实际技能安装。
6. 使用显式注册 DeepSeek Flash并保留实际身份/后端修订未知边界。固定失败位置，
   不重抽、不接受新基线。报告定向理解、自然接手、成本与未过门槛，决定保留或
   撤回，再本地提交到开发分支。本轮不推送或发布。

## 审查重点

分布必须包含被省略的普通引用和异常诊断；重复目标不可去重；记录行不可误删。
当前漂移与历史完整分开，校验成功不等于测试全绿；执行期变化后恢复 MATCH
仍显示原变化。联合条件与实际次数分开，不把这些信息当唯一执行数或历史不可篡改证明。

## 第一版与修订

第一版 `a06f714` 增加静态 `omission_policy`。五次新对照与五次候选对原两类
误读均为 5/5 正确，不能声称这批证明了行为提升；宽六项仅为 3/5 → 4/5。
候选仍有人误称全为 RECORDED 时完整/紧凑两种输出无差，忘记字段投影与新增元数据。

修订版保留分布，将静态规则替换为本次实际 `omissions`：LINK_OK 的 `whole_rows`
为本次省略数量；RECORDED 的 `whole_rows=0`，`field_only_references` 在实际压缩
分支计数，`fields` 仅在发生投影时列出两字段，否则为空。计数仍是引用出现次数。
指南继续说明联合压缩条件。原字段与行不变，不增加工作步骤。

第一版原定 22 次前向继续完成并单独封存。标准轮 `20261126T111649Z-standard`
在修订决定后停止：113 槽完成、16 槽运行中中止、82 槽未启动；不能当完整标准。
修订版另冻结源/输入/模型与 5 个新定向、6 个新自然候选读者，明确复用原来
5 个定向和 6 个自然对照，不混第一版候选；最终修订版必须另跑完整 211 标准。
