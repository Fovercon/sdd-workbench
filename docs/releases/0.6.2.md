# v0.6.2 发布记录

这次补丁发布了几轮优化里可复用的示例、评测用例和维护工具。12 个技能的 76 个运行文件与 v0.6.1 逐字节一致。已有项目可以继续使用原来的切片、任务表和交付流程。

## 使用者能用到什么

- 切片完成后，可以把同一次检查的命令、结果和所测版本记录在一处。任务表记录当前进度并指向回执。示例给出了可直接复制的相对链接，也说明了旧任务卡被覆盖时如何识别断链。[切片记录示例](../optimization/SLICE-COMPLETION-RECORDS.md)
- Finish、Implement 和 Router 的专项评测覆盖限写授权、交付报告中的代码示例、接手时的失效引用，以及实际取得技能正文的时点。源码工具可在 Pi 原始日志中定位工具何时返回指定全文，或将已观测的文件写入与明确授权逐条比对。只读命令检查需要 Linux、Bubblewrap 和可用的用户命名空间。[维护工具及用法](../../evals/context/README.md)

## 实际评测结果

双切片项目各跑 5 个原版和 5 个实验候选。即使候选加入“同一检查只记一次”的提示，两组仍各有 30/30 次检查在两份文档里重述了命令和结果。这段提示保留在实验分支。另做的接手试验中，使用一份记录加引用的 9 个会话和使用三份全文的 9 个会话都找回了原始证据，并执行了当前要求的检查。接手材料只有一条短记录，完整开发试验也只覆盖一种任务，尚未证实全流程降本。[开发分支上的试验记录](https://github.com/Fovercon/sdd-workbench/blob/4f8cf4421e7b3c16c4a703e9ccfcb50b784500fe/docs/optimization/POST-0.5.0-PLAN.md)

本版复用相同运行内容在 v0.6.1 发布前取得的标准评测。批次 `20261123T062902Z-standard` 完成 211 个模型试次，13 项门槛达到 8 项，强制完整流程的累计 token 比为同批裸模型的 52.01 倍，目标为 8 倍以内。模型登记为 `deepseek/deepseek-flash`，服务端修订未报告。[历史标准评测及限制](0.6.1.md)

## 本版发行验证

本地通过 393 项 Python 测试（主套件 107、Router 178、维护协议 108），以及 Node 适配、包内容、Chromium 交互和恢复回归。两次构建的 ZIP、文件清单和 SHA256SUMS 逐字节相同。发行 ZIP 中 76 个运行文件均与上述标准评测的冻结输入逐文件比对。

Codex、Hermes、ZCode、DeepSeek Harness、OpenCode 和 Pi 各使用独立临时安装目标验证从 0.6.1 升级、回退和重新安装。六次注入已编辑的受管文件，安装器都在写入前停止，未管理文件完整保留。回退后的 12 个技能在每个目标都逐文件匹配 0.6.1。
