源码仓库的维护者还可以回放上下文包审计、计量重复回传的测试输出。项目明确要求独立 SHA-256 清单时，可从约定中取得预期路径，逐项检查清单覆盖和最终字节。安装技能不需要这些维护工具。[维护工具与用法](../../evals/context/README.md)

## 模型验证

保留版本与旧版本分别在两个场景各跑五次。双切片本地开发的累计输入中位数（含缓存）由 3,775,794 降至 3,294,110，未缓存输入中位数增加 0.8%。明确要求使用检查点的任务，两版各五次均识别出需要业务决定，模型请求数中位数均为 7。定向样本中仍出现范围遵守偏差。

标准回归 `20261123T062902Z-standard` 的 76 个运行时文件与本次发行的技能运行时逐字节相同。211 个试次全部结束，13 项门槛通过 8 项。评测登记的模型为 `deepseek/deepseek-flash`，服务端修订号未提供。

| 未过门槛 | 观测值 | 目标 |
|---|---:|---:|
| 输出使用约定枚举 | 0.8947 | ≥0.9 |
| 强制流程与裸模型的累计 token 比 | 52.0111 | ≤8 |
| 声明启发式标记数，需逐条人工复核 | 12 | 0 |
| 字面追溯覆盖 | 0.4708 | ≥0.8 |
| 可见与隐藏测试分差 | 0.6 | ≤0.5 |

强制流程与裸模型的累计 token 分别为 72,792,774 和 1,399,562，包含缓存读取。Pi 客户端估算的费用比为 9.15，未经账单核对。本次没有接受新的评测基线。后续试验中的验证复用提示和简化 Finish 记录均只保存在实验分支，其试验收益不计入本版。[开发分支的取舍与数据](https://github.com/Fovercon/sdd-workbench/blob/c6a3a6539c6fc898126aca53d69d890d234fc2de/docs/optimization/POST-0.5.0-PLAN.md)

## 发行验证

本地通过 377 项 Python 检查（主套件 107、Router 178、维护协议 92），以及 Node 适配、实际打包清单、真实浏览器交互和恢复流程回归。两次独立构建产生相同的 ZIP、manifest 与 SHA256SUMS。ZIP 包含 12 个技能，外部清单列出 216 个文件。

在六个临时安装目标中，从已发布的 0.6.0 升至候选包，再回退并重新安装，两版受管技能均与对应发行包逐字节一致。六组本地修改均触发覆盖保护，非托管文件保留。

标签工作流在 CI 通过后构建 ZIP、逐文件 manifest、SHA256SUMS 和 Sigstore 来源证明。下载后可核对包内容、构建工作流以及标签对应的源提交。[验证命令](../../SECURITY.md) · [标签工作流](https://github.com/Fovercon/sdd-workbench/actions/workflows/release.yml)
